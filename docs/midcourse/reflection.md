# Reflection

I used Codex as the main AI coding collaborator for requirements review, architecture decisions, implementation, test generation, and evidence gathering. I used the course materials as the source of truth rather than allowing the assistant to infer a generic task tracker. Chrome was used for live checks of the empty board, task creation, due-date and tag rendering, priority order, and the overdue filter. Pytest and small command-line checks supplied the strongest evidence because they made status codes, response bodies, and deliberate regressions repeatable.

AI helped most when it connected one requirement across all layers. For example, due dates were not treated as only a form field: the change included Pydantic parsing, update and clear behavior, storage filtering, a card indicator, and tests for future, past, and completed tasks. The same end-to-end framing kept tags consistent from normalization through filtering and display. The prompt constraints also prevented a database, ORM, frontend framework, and other scope growth that would have hidden the course workflow.

AI also slowed the work in two useful ways. First, the initial edit-form approach sent the full task payload on every PATCH. My review caught that an unchanged status would be rejected by the existing same-status transition rule. I changed the frontend to compare the form with the original task and send only changed fields. Second, a Windows UI helper stopped when it could not confidently identify Chrome's URL. I accepted that safety boundary and continued with test and local-browser evidence instead of trying to bypass it.

My review changed the result most clearly in the definition of overdue work and tag storage. I rejected date-time/timezone complexity in favor of an optional date-only field, and I excluded Done tasks from overdue results. I also rejected a normalized Tag table because the project intentionally uses in-memory storage. Finally, the two break tests strengthened my confidence: removing lowercase normalization and weakening the overdue comparison each caused the exact focused test to fail. The habit I will reuse is to specify one bounded change, inspect the assumptions, run a focused check, deliberately prove important tests, and only then refactor or expand.
